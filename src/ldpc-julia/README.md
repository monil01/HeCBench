# LDPC: full WIMAX normalized min-sum decoding

Historical Julia source/Makefile and all native sources are preserved intact. The old Julia program hard-thresholded constant positive LLRs and printed fabricated bit/frame error statistics without the parity graph or message updates. The restored CUDA.jl/KA/JACC implementations execute all four native logical stages across ten fixed iterations: first/normal check-node processing and normal/final variable-node processing. Each batch has20 ordered kernel launches; the complete three-batch trial has60. Native kernel bodies, WIMAX96 lift and CW2 local geometry are unchanged.

## Independent scientific checks

The original12x24 QC base graph expands to2304 variables,1152 checks and7296 edges. A generic independent GF(2) Gaussian parity solve has rank1152 and constructs deterministic nonzero codewords; full syndrome checks prove their validity. Three named batches contain two noiseless encoded codewords, four encoded codewords with four weak sign errors each, and two neutral all-zero LLR controls. An independent Tanner-graph oracle enumerates every excluded edge when taking minimum/sign products, rather than copying the source two-min algorithm, and rounds each operation to Float32. Normalization.75, initial minimum cap1000, compact graph ordering and source tie semantics are retained.

All six nonzero encoded clean/noisy controls decode to their transmitted bits with zero syndrome/error counts. These deterministic checks are not a BER/FER or SNR reliability estimate. The zero-information controls intentionally reproduce APP0→hard1, giving all-one hard vectors and syndrome weight384 percodeword. They contain no channel information and are not successful valid-codeword decoding claims or framework accuracy failures. Their error counts remain separate from the six known-codeword checks. The historical stub used APP>=0→hard0 and therefore disagrees even on this tie rule.

## Mapping, failures and timing

All paths use96x2 threads, source CW2 and CNP grids12xMCW/VNP grids24xMCW, with named MCW1/2. HElement retains the exact4-byte four-Int8 native structure. Normal CNP uses5376 bytes shared old-R cache and the source barrier. KA/JACC use ordinary Julia arithmetic/structure access and their own indexing/shared-memory/barrier APIs, without CUDA device intrinsics. Only the CUDA backend is tested. JACC explicitly requests5376 bytes for normal CNP and0 for other stages; its full shared-template initialization/copy/barrier is recorded as extra work. KA uses equivalent local memory. Native/CUDA.jl use dynamic shared allocation. The first native measurement adapter failed C++ pair initializer-list type deduction; a typed array fixed this host adapter. No native GPU candidate was rejected. CUDA.jl, KA and JACC each pass their first actual GPU candidate/check.

Five checked in-process trials each sum three complete20-kernel pipeline launch/completion regions; only trial1 timing is excluded. There is one completion perbatch and no host synchronization between ordered stages. Input copies, state resets, initial GPU input readback, graph setup, encoding, JIT warmup, final readback, oracle and serialization are outside. Per-batch times remain. Source iterations are fixed even when clean words decode earlier. This is not the original MCW40/500-repeat AWGN Monte Carlo walltime, measured channel reliability or a device roofline point. WIFI81/log-SPA/other lifts remain unverified, not declared framework limitations.
