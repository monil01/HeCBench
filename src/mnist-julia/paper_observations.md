# MNIST paper observations

- **RQ1 — fidelity:** All 19 source GPU definitions and the complete two-epoch learn/test pipeline agree across four models on 100/20 exact original MNIST images. Five trials/model retain all stage arrays, exact input readbacks and actual guards. Independent dense LongDouble equations check 20.1 million local values/model; a separate BCE finite-difference witness supports the source's preconditioned gradient interpretation. Initial weights precede the visible seed call and must be read back. The small run gets only 2/20 classifications right: numerical fidelity is not application accuracy.
- **RQ2 — feedback and effort:** First complete GPU candidate passes in all three Julia models. A native observer C++ type error and separate CPU evidence/metadata errors are shared infrastructure events, not target-kernel failures. Actual context-inclusive target windows consume 1,507,783 / 1,593,744 / 1,999,284 tokens. Shared-harness creation and prior-model evidence work make the first two windows unsuitable for clean target-cost estimation. Later targets reuse validated bodies and host logic.
- **RQ3 — execution:** Last-four means are 36.73 / 41.82 / 50.97 / 69.77 ms for CUDA / CUDA.jl / KA / JACC. They describe the instrumented complete source pipeline, including host work and observer completion fences. Full-dataset and untouched allocation/CLI timing claims are excluded.
- **RQ4 — mechanisms:** The study preserves 64×64 source index partitions, 4,780 launches/trial, Float32 atomic reductions and complete host norm/copy work. All three use their own framework atomics; KA/JACC need no CUDA device helper. JACC requests shared memory zero explicitly. No profiling/controlled host-launch experiment establishes a causal performance mechanism or roofline position.
- **RQ5 — selection:** All three abstractions express this source CNN, including shared learned filtering and reductions. Choose based on deployment and validated scope; these single-V100, small-data pipeline timings cannot establish universal target superiority, training convergence or cross-backend availability.

Complete records, hashes, actual raw/primary joins, error bounds, usage-window scopes and limitations are in the neighboring JSON and README.
