# Pointer chasing: original assertion-only execution study

The native kernel follows real 64-bit device pointers and asserts that the final pointer is non-null. It has no numerical store. This primary study therefore certifies checked execution only and is excluded from numerical-agreement counts. No artificial sink output is added to the timed kernel.

The original two-megabyte allocation contains 262144 eight-byte nodes with successor(i)=(i+16) mod262144. The active cycle from node 0 contains 16384 nodes. Each selected block performs 1000000 dependent pointer loads. Every device-SM-count block ID is selected in a separate launch using the original grid of SMcount blocks and one thread per block. A block ID is not an SM ID: the source does not establish affinity to a particular physical SM.

Historical CUDA.jl used a UInt32 index array, halving allocation size and introducing an index representation. Its source and Makefile are preserved. The current CUDA.jl/KA/JACC versions retain actual eight-byte device addresses and a nonvolatile global 64-bit load, using an explicit LLVM backend extension and CUDA device assertion. These are CUDA-specific backend extensions, not framework-independent pointer APIs. The original native kernel remains unchanged through a source include.

## Auxiliary diagnostics

Outside the timing region, every trial reads back all 262144 device pointer values and checks them against the actual allocation base plus the exact successor offset. A separate diagnostic kernel returns final pointers after 0, 1, 17 and 1000000 accesses. Their required offsets are 0, 128, 2176 and 73728 bytes. Raw allocation bases, the entire raw pointer graph and all four raw cursors are retained in persistent per-model ignored diagnostics files. Device addresses naturally differ between processes; their raw equality is not claimed. A read-only Python audit independently checks every saved word and hashes each file. These diagnostics do not turn the original assertion-only kernel into a numerical-output benchmark.

Each checked trial times the sum of all target-block launch+completion regions. Setup, pointer initialization, readback, auxiliary diagnostics and compilation/warmup are outside. Native initialization retains its per-node copies; Julia bulk initialization constructs exactly the same logical device-pointer graph outside timing. Both use a full original-workload warmup. Five raw trials remain and the mean uses trials2–5. The reported nanoseconds per access include host launch and synchronization; they are not isolated hardware load latency, cache-hit latency or SM affinity measurements. Neither cache traffic nor actual executed load counts are inferred without profiling.

The primary structured contract records source_empty_kernel=false, source_no_observable_numerical_outputs=true, no_output_reason=source_final_pointer_assertion_only, source_final_pointer_assertion_checked=true, pointer_graph_checked=true, device_completion_checked=true, nonnull_final_pointer_checked=true and pointer_storage_bits=64. checked_values=0, numerical arrays are empty, errors are null and numerical_agreement_claim=false. There is no primary binary output artifact or serialized input prefix. The separate full raw graph checks establish the actual pointer representation and graph invariants without equating ASLR-dependent addresses.


Separate static inspection retains a loop and __assertfail in all four entry PTX captures. Native PTX uses generic ld.u64. Julia entry PTX calls an externally linked LLVM pointer-load helper; its body and final SASS were not captured, so identical load instructions or cache behavior are not claimed. A standalone reflection-wrapper include-path error was fixed after verification and is a shared T1 instrumentation event, not a device translation candidate or a failed primary trial. The measured sources and times are unchanged.
