# SRAD: conditional corrected statistics reduction and full diffusion pipeline

The native README describes speckle-reducing anisotropic diffusion for ultrasound/radar imaging and its role in a Heart Wall image-processing pipeline. This study checks the numerical image operator and discrete invariants, not clinical interpretation, perceptual denoising quality or the full tracking application.

## Numerical contract and evidence

Four column-major images have16x16,19x27,3x257 and257x257 pixels, with2,3,2,3 steps and lambda .5,.5,.125,.75. The deterministic gray values are15–240. Global variance stays well away from zero; the minimum oracle q0² is about .0224. Uniform and near-zero-variance images encounter an unhandled q0 division domain in the original operator and are outside certification, not a framework capability limitation.

Every step prepares image and squared-image arrays, reduces both through the original256-thread tree, reads totals to the CPU, computes Float32 global mean/variance/q0, then launches coefficient/derivative and diffusion-update kernels. Reflecting neighbor maps and clipped coefficients0–1 are retained. Extraction exp(raw/255) and compression255log(J) are also executed and checked. An independent Float64 oracle uses mathematical global sums and conservative pairwise edge-flux assembly rather than copying the native pointwise divergence. Full partial-workspace nodes and stale nonreduced entries are checked too.

All20 trials pass the complete815311-word contract:69310 exact input-prefix words plus746001 full image/workspace/statistic/echo/guard words. Captures include compressed and precompressed final images, actual extracted initial images, both complete sum workspaces, all four derivatives, coefficients, every iteration's five scalar statistics, actual raw inputs and neighbor maps, and768 guard words. Inputs, guards and reflecting outward-zero derivatives are checked exactly. All coefficients remain0–1, the final maximum principle holds, and actual extracted-image mass relative drift is at most1.95e-9. Full intermediate GPU image trajectories are not captured; all iteration scalar statistics are.

## Mapping, timing and effort

All versions retain256-thread pointwise grids and reduction chains1;3→1;4→1;259→2→1. Partial tails, mul256 and three reduction levels are exercised. Native reduction has two256-float static shared arrays; Julia versions use one512-float buffer split into the same logical planes. KA uses its own indices/local memory/barriers. JACC uses its own dispatch/shared/workgroup APIs with2048 dynamic shared bytes for reduction and zero for all other kernels. Its installed shared API copies the entire512-float template and adds an entry barrier. Actual registers, bank placement, occupancy and generated instructions remain unprofiled. No CUDA-specific device intrinsics are used by KA/JACC; only CUDA backends have been tested.

Primary timing matches the source's COMPUTE region: all iterations of preparation, reduction, two scalar D2H copies, CPU statistics, coefficient and update kernels, plus completion. There are51 timed launches and20 scalar D2H copies per trial. Fifty preallocated Float32 observer stores are inside timing in all versions; this shared instrumentation is an explicit covariate. Extraction/compression are outside primary timing, with their own stage clocks retained. Allocation/reset, full readbacks, checks, serialization and explicit all-case warmup are outside. Five checked trials remain and only timing1 is ignored;2–5 are averaged without outlier removal.

These are mixed host/device timings, not isolated kernel latency or a basis for roofline attribution without profiling. The four cases also vary image content, lambda and step counts, so their per-case times are not a controlled scaling sweep. Neither original1000-step CLI performance nor generic abstraction superiority is established.

Current CUDA.jl/KA/JACC candidates each compile and pass their first check, with six authored entrypoints per version. The original native indexing failure is separate from compiler feedback; historical input/timing defects are separate source findings. Shared pointwise helpers, scientific oracle, correction and adapters are attributed once to reference preparation; KA/JACC separately author their reductions and dispatch. Prospective usage windows include repeated/cached context and coordination, overlap the workflow and must not be summed or interpreted as exclusive billed or independent cold-start framework costs. Historical creation cost remains unknown.
