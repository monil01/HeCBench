# TQS: persistent block task queue with initialized terminal padding

The IMPACT task-queue benchmark measures dynamic scheduling of synthetic heavy/light integer tasks. Its README cites Chen, Villa, Krishnamoorthy and Gao's2010 dynamic load-balancing work; no scientific application or corresponding published performance is claimed. Historical Julia computes a genuine expected integer value but statically assigns one block per task and replaces the repeated work by a closed-form expression. This study restores the original persistent atomic queue, shared task broadcast, block barriers and actual addition loops. Equal numerical outputs alone would not demonstrate preservation of this scheduling workload.

## Conditional allocation scope

The original kernel's block leader calls atomicAdd(consumed,1), then unconditionally loads queue[next].id/op before testing next<logicalQ. Every block eventually needs a terminal token, so after Q valid tasks the B blocks collectively claim indicesQ...Q+B-1 and leave counterQ+B. The original host allocates only Q records. This is a source-bounds defect, not an observed old GPU fault: no known-invalid original allocation was run. Static sm70 nvcc12 PTX also places the queue loads before both branches, but generated loads are not a dynamic fault trace.

The native kernel body stays byte-identical. The owned study host allocates Q+B physical records and initializes the B terminal records to sentinel{id=16384,op=16384}; logicalQ and task work remain unchanged. This minimal host-allocation intervention is explicitly native_reference_repaired and conditional, excluded from untouched-native aggregates. Standard64-task-record outer guards surround the physical task allocation; data and counter have64-word guards. Payload pointers remain256-byte aligned. The original CLI allocation is not certified. queue_bounds_locator_erratum.json corrects a handcopied line-number field in the preserved original witness; exact source hashes, range proof, execution and acceptance are unchanged.

## Complete contract

Four named controls use T/B/Q/pool/iterations=(32,3,7,21,0),(64,320,320,640,3),(128,7,17,51,9),(256,5,3,9,1), with mixed, all-heavy and all-light patterns. Every pool is a multiple of the queue length. These are short controlled cases, not the original1000-iteration/1000-repeat/pattern-file CLI. All11 chunks execute the real persistent block queue. The independent oracle uses bounded exact integer arithmetic only to check the executed results; it does not replace GPU work.

All20 full162001-word artifacts match exactly, including742 input-prefix values and161259 complete state values. Each chunk captures actual prekernel zero device data, full postkernel data, every device task record and initialized terminal record, final atomic counter and all guards. The final whole host pool and original CPU written counter are also checked. Every logical task's full lane vector has the expected value, counters equalQ+B and all guards/padding remain exact. For zero-heavy taskID0, a zero result cannot by itself prove an executed add-zero operation; source atomic-claim uniqueness, counters and complete outputs are the evidence, not dynamic arithmetic counters.

The original CPU host_insert_tasks body performs the same queue/data memcpy and written-count increment in all four models. Native includes the original implementation; Julia calls a thin C ABI wrapper compiled with GCC13.3.0 -O3 -fPIC. The exact helper library is hash bound and rebuildable by make host. Julia uses CUDA transfer/stream wrappers and native runtime copies; host API overhead is a mapping covariate. KA/JACC device indices, Atomix old-value fetch-add, shared arrays and barriers use their own frameworks. CUDA.jl/KA use3 static shared Int32 values; native allocates12 dynamic bytes and JACC uses12 dynamic bytes plus a3-element template copy and entry barrier. No other backend is certified.

The ROI includes host data reset, CPU enqueue, three H2D copies, persistent kernel and original payload D2H for all11 chunks. Four additional complete observer D2H copies per chunk are inside every model's timed region: actual zero input, full output/guards, queue/padding and counter/guards. These44 observer copies are a substantial small-workload instrumentation covariate. Allocations and staging arrays are preallocated; JIT/full-pipeline warmup, independent checks, serialization and artifact assembly are outside. Five checked trials retain every sample and average2–5; per-case clocks are saved. This is mixed CPU/GPU pipeline latency, not kernel-only throughput, load-balancing scalability or measured arithmetic work/roofline data.

The first reference host process had an owned comprehension-whitespace parse error before any GPU compilation; its source and raw log are archived. The unchanged current CUDA.jl kernel passed its first actual device check on the second host process. KA and JACC each pass their first candidate/check with one authored kernel entrypoint. Shared helper, allocation proof, oracle and pipeline preparation are counted once in the reference phase. Prospective model windows are ordered marginal context-inclusive usage, overlap the workflow and cannot be summed or treated as exclusive billed or cold-start framework costs. Historical creation cost is unknown.
