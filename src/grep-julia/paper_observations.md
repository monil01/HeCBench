# GREP observations (RQ1–RQ5)

- **RQ1:** All 20 complete 2,391,596-value Int32 captures match exactly against both GPU references and Python byte-regex fullmatch; the actual-input prefix has 1,523,696 values. All four models additionally capture 5,120 actual untimed NFA graphs each. The original CLI demonstrably drops a final unterminated line; the primary uses terminated inputs and preserves that boundary witness.
- **RQ2:** CUDA.jl: three program checks, including one frontend ParseError before device JIT and one actual GPU private-list heap failure; two device-JIT processes. Flattening list objects into one workspace with scalar base swaps resolves the failure. KA and JACC each pass their first candidate/check. The formal matching algorithm and exact tolerance remain unchanged.
- **RQ3:** Means of trials 2–5 (ms): native .879100, CUDA.jl 11.920406, KA 11.992353, JACC 13.897734. Each interval includes all 30 GPU regex-parse/NFA-build/match launches and completion. Source 512×160 launch geometry remains unchanged, including mostly idle threads for the smallest corpus. This is a named resident component scope, not whole CLI timing.
- **RQ4:** Pointer graphs and patch lists become Int32 indices; packed shared bytes and flat private lists change storage and resource demands. Native compilation reports 28 registers, 17,616 B stack, 12,016 B shared and no spills. Julia requests 9,224 B shared; JACC adds a 2,306-value preload. No profiler/roofline or causal account of the timing gap is claimed.
- **RQ5:** All three frontends express on-device compilation and irregular traversal without a foreign CUDA device extension. The repair demonstrates the importance of private-array representation. Arbitrary regex capacities, nullable epsilon cycles, Unicode and full CLI input boundaries remain outside the certificate.
