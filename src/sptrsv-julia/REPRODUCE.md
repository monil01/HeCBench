# Reproduce the custom sparse triangular solver

The LP1 input archive is the existing tracked `src/sptrsv-sycl/lp1.mtx.tgz`. The source reader expands its symmetric pattern, replaces strict-lower values by one, and adds a unit diagonal. This is not the original numerical optimization problem. `extract_source_fixture.cpp` calls the actual original CPU headers; the independent Python generator checks every CSR row, known solution, row grouping, and dependency depth and uses exact rational forward substitution on the compact controls.

From the repository root, create `.porting-state/portable_julia/sptrsv_reference_review`, extract `lp1.mtx` there, compile `src/sptrsv-julia/extract_source_fixture.cpp` with `g++ -O3 -std=c++17 -DWARP_SIZE=32 -DWARP_PER_BLOCK=8 -DVALUE_TYPE=double`, and run the extractor in that state directory with `lp1.mtx`. Then run `python3 src/sptrsv-julia/generate_fixtures.py`. The committed CPU-generated `input_f64.bin` and `oracle_f64.bin` are essential fixtures; GPU captures stay outside Git.

`study_original_kernel.cuh` preserves the original kernel. The primary measured configuration instead includes `study_corrected_kernel.cuh`: the only mathematical-reference intervention is explicit warp synchronization after the shared sum store and after every reduction stage. The exact patch, five original failing captures, full mismatch witnesses, and conditional reference provenance are retained. The untouched source passes the named thread-row LP1 case but fails the varied-right-hand-side warp controls. Correction is not a proof of race freedom or scheduling progress on other devices.

Run the study through `tools/verify_portable_julia.py --config src/sptrsv-julia/study_config.json`. It serializes GPU 6 internally; do not put an external GPU lock around that command. Remove `reuse_result` and `reuse_models` only when intentionally creating a new complete twenty-trial measurement. Each of five checked trials contains three solves per case, with x/flags reset outside every timed interval, kernel and device completion timed, and all actual x/flags saved after each solve. Performance discards only trial 1 and averages trials 2--5; internal repeats are not a three-trial measurement.

All three Julia implementations retain the custom solver, static/source 256-thread geometry, and two row mappings. Their volatile Int32 LLVM helpers and CUDA device fences/warp synchronization are explicit backend extensions. JACC additionally copies a 256-double global template into dynamic shared memory and executes its initializer barrier plus the explicit uniform wrapper barrier before any return. No vendor triangular solve replaces the authored kernel. The CPU oracle is never uploaded.
