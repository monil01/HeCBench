# Constant-memory checksums: actual interface and observable work

## Declared contract

Original full grid 4,194,304 workers / 256 threads / 16,384 blocks and all three source access widths (int/int2/int4, 4/8/16 bytes). Each computes a checksum of 1,024 constant Int32 words, but only thread0/block0 stores one Int32. Original device `repeat` parameter is unused. We time R10 host launches per width and report the sum of the three per-launch means, preserving individual width times in every trial. Original ones input gives exactly1024. Additional untimed signed23-value controls give exactly1, all three widths every outertrial. Actual constant-symbol readbacks, parameters, all six checksums and192 guard words form the complete6,372-Int32 artifact, with6,174-word exact input prefix. Independent Python integer construction audits all20 full saved outputs exactly; no tolerance or nondeterministic normalization.

## Native work counterexample

Native PTX places loads before its writer predicate, but actual sm70 SASS exits all nonzero thread/block workers before constant reads for ALL three widths. Static original and measured-adapter cubins have identical device instruction words. `native_work_observability.json` retains exact source/SASS hashes and instruction prefixes. This is **kernel latency**, not measured constant-memory bandwidth or a roofline coordinate based on intended all-worker bytes. Numerically correct checksums alone would not detect this loss of observable work. Julia full-module PTX proves true const4096B and scalar/v2/v4 loads, but Julia final SASS/dynamic traffic remain unreviewed; no claims about physical load volume.

## Abstractions and extension boundary

Historical CUDA.jl uses ordinary global CuArray/scalar reads and could pass the checksum without preserving the constant-memory interface. It is archived unchanged. All three current Julia models explicitly declare an LLVM `externally_initialized` address-space4 global with SIMD vector loads, initialize/read back its actual compiled module via CUDA.CuGlobal, and retain normal CUDA.jl/KA/JACC dispatch. All are **hybrid_device_intrinsics**, including CUDA.jl because this is a custom LLVM backend extension; CUDA.Const alone is not an equivalent allocation. KA and JACC compiler hooks are pinned implementation details used outside ROI to bind the same cached module, not substitute CUDA launches. JACC explicitly requests zero dynamic shared memory. Julia width-specialized modules have distinct globals versus native one global; each case is separately initialized and warmed. Allocation, compilation, initialization/readback and untimed controls stay outside ROI, whole-device completion closes each timed loop.
