# SA native readiness and prospective study scope

SA constructs a lexicographically ordered suffix array using DC3. The source consumes raw genomic ASCII; it does not perform alignment or infer a biological endpoint. The unchanged real 1,000,000-symbol input produced a full valid suffix array in a separate capture-only execution. The complete independent certificate checks permutation and adjacent `(first symbol, inverse rank of the tail)` ordering; finite-tail descent establishes the unique complete lexicographic order. This is stronger than the source's scalar checksum and is not a second DC3 transcription.

The primary study preserves the advertised 1,000,000-symbol / 100-construction case. Each of five checked outer trials starts from the original zero suffix buffer, then feeds the previous host suffix array back into the next device assignment, as the source does. It checks the final construction of each trial, not every internal construction. Fourteen separately named R1 controls exercise unique, uniform, periodic and real-prefix inputs and all three remainder classes. Their timings are diagnostic and excluded from aggregate rankings.

The study appends 17 external input/output guard words beyond the source's three zero sentinels. Original private Thrust workspace sizes and zero constructors are preserved; no private workspace guard claim is made. Source custom GPU bodies remain unchanged. Warmup, full actual device-input readback, independent certification and artifact serialization are outside the measured region. The region includes source input/prior-output transfers, all recursive DC3 device stages, Thrust allocations/sorts/scans, GPU rank feedback, host recursion, workspace destruction and final suffix-array transfer, followed by whole-device completion. The per-construction time is the total source repeat region divided by its repeat count, not process startup.

Targets will implement the nine custom GPU definitions and host recursion. The shared C ABI exposes only the original standard Thrust container/sort/scan operations; it cannot solve DC3 or call custom source kernels. All models use the legacy stream and whole-device fences. Original Thrust primitives are retained for fidelity, not because portable sorting/scanning was established unsupported. The mixed kernel/library and data-dependent host control boundaries preclude a pure-frontend or kernel-only causal interpretation.

The appended guards, separately warmed protocol and shared-runtime link are integration/resource adaptations, not a mathematical native repair. The study excludes untouched-native aggregate comparisons. Native preparation included discussion of this common architecture before any target code or target phase window; target cost metadata must disclose inherited context and this prior planning. The source attribution is retained; no SA-specific license file was found and no other benchmark's license is assigned.
