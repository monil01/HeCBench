# Central moments and reduction API

The original native kurtosis function returns count, mean and unnormalized central sums M2, M3 and M4, plus its 20-byte result size. It does not return standardized or excess kurtosis. Derived Pearson kurtosis is analysis only and undefined when variance is zero.

Seven finite fixtures include singleton, symmetric, source-domain positive, outlier, zero/constant and signed distributions, up to 4099 records. Every input retains the 24-byte native record layout. Padding is initialized outside timing and captured explicitly; the GPU operator reads the value field. Inputs and all input guards, result count/size and zero moments on constant fixtures are exact. Full means and moments use predeclared, scale/recentering-aware budgets against independent Float64 direct central powers. The broad generic artifact-comparison envelope does not replace these stricter fieldwise checks. No tolerance is adjusted after measurement.

Native Thrust and its functors are unchanged. Julia uses genuine framework dispatch for two-stage, 256-thread pairwise summary merges. Different reduction trees, vendor implementation, allocators and host runtime are explicit performance covariates. Empty inactive partials are skipped as identities. Native internal partials and allocation guards are opaque; no matched internal-workspace or output-guard claim is made.

The region preserves the complete reduction API: temporary allocation, computation, scalar device-to-host retrieval on each repeat, and final host result creation. Julia temporary arrays are allocated/freed inside each operator call. Input setup, compilation, complete input capture and CPU oracles are outside. Each of seven regions is divided by ten repeats; five checked trials retain all samples and average trials two through five. These are host/device API times, not isolated kernel latency or a causal abstraction penalty. The original 100-million-record CLI and a full scientific time-series application remain untested.
