# CCL: genuine two-rank NCCL collective interoperability

This benchmark bootstraps a two-rank NCCL communicator through host MPI and calls `ncclAllReduce(Float32,sum)` on an explicit CUDA stream. The original source contains **zero authored device kernels**. Julia versions own framework allocation, the repeated collective loop, timing and cleanup, calling a narrow MPI/NCCL C ABI for individual operations. KA/JACC package use does not establish a backend-independent collective implementation. Whole implementation class: vendor-library interoperability and host orchestration.

The named contract uses physical GPUs5,6 under the central GPU study lock and an additional GPU5 idle/owned-rank PID guard. It covers17 zero elements,1,048,576 original all-one elements and10,485,760 rank-dependent dyadic elements,50 collective repeats per region. All four versions capture complete actual send/initial receive arrays, both guards, final receive arrays and readonly send arrays from both ranks. The exact sum oracle checks every value. Per-rank timings remain in raw logs; the reported statistic sums per-case maximum-rank seconds per collective. Allocations, H2D/readback, MPI barriers/reductions and full checks are outside the timed NCCL loop and explicit stream wait.

Every accepted series requires five checked trials and averages times2–5. Trial0 warms the whole three-case pipeline. `audit_outputs.py` independently recomputes Float64 sums from the actual full saved inputs and checks all outputs/guards without GPU execution. Full raw arrays stay local. This two-device, guarded-alignment configuration is excluded from single-device and untouched-original aggregates. It does not certify the source's100M/1B/default whole-CLI performance.

Original native readiness: the unmodified source was built with available MPI/NCCL include/library paths and passed all four original sizes at repeat1, including the1B-element case. This is a separate diagnostic, with source output checks and raw logs but no captured full original arrays. It is not the primary five-trial series.

Native adaptation failures and target interoperability failures are preserved separately. An initial adapter link omitted MPI C++ bindings; unused bindings were then disabled. The first full native checker series passed but its launcher exited nonzero after a denied `/proc/PID/environ` query; those captures remain diagnostic. Rank PID registration before GPU initialization and a fresh complete series fixed that guard. The first CUDA.jl series passed exactly. The first KA allocation/host-orchestration program stalled in the first17-element warmup stream wait and was stopped as an owned MPI job; no checked trial, unsupported-feature conclusion or allocation root cause is inferred. A bounded, separately named allocator-policy diagnostic follows.
