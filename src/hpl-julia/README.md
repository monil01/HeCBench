# HPL: full named single-rank factorization and solve

This product includes software developed at the University of Tennessee, Knoxville, Innovative Computing Laboratory. Original HPL2.3 sources and their license notices, including the Intel2023 CUDA integration, are preserved under `reference_history/`. Original `../hpl-cuda/` files were not changed.

## What was verified

All four paths execute the complete original C/MPI HPL panel, recursive factorization, swapping, update and triangular-solve pipeline on one rank. The named cases are N1536/NB512 and N257/NB64, generated by original `HPL_pdmatgen` with seed100 and original random right-hand sides. Leading dimensions are1544 and264; the first has eight more padding rows than original `HPL_pdtest` would select. These are bounded full-solver cases, not certification of the default24576 deck or distributed scaling.

The source contains **zero authored GPU kernels**. Its GPU work is cuBLAS FP64 DGEMM and DTRSM: eleven and one calls per trial, alongside884 CPU DGEMM and896 CPU DTRSM calls. CUDA.jl uses `CuArray`, KA uses its CUDA-backend `allocate` and copy, and JACC uses lowercase `JACC.array`. All three use explicit `CUDA.CUBLAS` interoperability and the original CPU solver through a C ABI. This is a library-backed allocation/orchestration study, not three portable mathematical kernel implementations.

The reference is explicitly qualified as `native_reference_repaired:true` / `corrected_reference_secondary`. Owned buffers retain the original extra solution/workspace allocation extent and initialize named padding. Mathematically inactive rows of read-only GPU staging A/B are normalized to zero; active coefficients, original host source buffers, output padding, operation options and thresholds are preserved. `reference_provenance.json` and `leading_dimension_scope.json` explain the intervention. The unchanged original integration otherwise copied arbitrary inactive scratch values:131072 such fields differed between retained diagnostic trials. No original scientific GPU defect is inferred. Untouched-native aggregate performance excludes this configuration.

## Numerical evidence and timing

Every trial records the complete actual device input spans and GPU outputs, initial coefficient/RHS bits, both final matrix/solution arrays and outer guards. Each GPU operation is independently checked with CPU BLAS on immutable pre-call snapshots. Every equation row is checked using extended CPU arithmetic for Ax-b, with backward-error budget1e-12. The observed maximum is6.14e-16. Direct four-way comparison uses declared absolute/relative budgets1e-8; all20 complete artifacts actually have identical bytes. Independent stage budgets are1e-9 absolute plus1e-9 relative. Uncomputed relative-error telemetry is null.

`audit_captures.py` independently reconstructs initial bits with a Python64-bit LCG, recomputes full GEMMs and explicit unit-lower forward substitution, evaluates every residual row, and checks exact captured outer guards. It fully rehashes all20 files and reuses mathematical replay only after identical complete SHA256. NumPy2.2.6 is an analysis dependency; extended precision on the recorded host has a64-bit mantissa. No condition-number, forward-error or peak-FLOP guarantee is claimed. Captured guards cover the matrix/workspace outer8 and solution tail8; no extra device-allocation guard was added or claimed.

Exactly five checked trials follow a complete unmeasured warmup. Only the first timing is discarded; the mean uses trials2–5. The region is the complete host-inclusive `HPL_pdgesv` solve minus explicitly clocked observation/input-readback/CPU-oracle intervals. Initial generation and final serialization/residual checking are outside it. This is not continuous CLI time or kernel-only time. Native `cudaMalloc/cudaFree` and framework allocation pools differ, as do legacy/modern cuBLAS host APIs; timing differences do not identify an abstraction or hardware bottleneck. CPU BLAS threads are explicitly1 in all selected processes.

## Reproduction

The recorded environment uses Julia1.12.6, CUDA.jl6.2.1, KA0.9.45, JACC1.4.0, CUDA12.0.140, OpenMPI and existing Julia OpenBLAS0.3.29. Exact project/preferences/Manifest and library hashes are in `environment_provenance.json`. CPU scalar arguments pass through the explicit HPL LP64→OpenBLAS ILP64 bridge. No OS package install or privilege escalation is required or performed.

From the repository root on a compatible configured CUDA/MPI host:

```sh
python3 src/hpl-julia/make_config.py --output /tmp/hpl_config.json
python3 tools/verify_portable_julia.py --config /tmp/hpl_config.json
```

The config producer drops historical capture reuse, resolves the current Julia executable and OpenBLAS path, and binds a new explicit path-relocation wrapper. `--source-root`, `--julia` and `--openblas-library` override those locations. It does not modify measured scripts, old configs, old sources or historical captures. Different libraries/toolchains constitute a new environment. The central runner owns GPU6 serialization; do not add an outer lock around it. Original Makefile instructions and data decks remain archived but are not the named protocol.

No binary fixture download is needed: original runtime generation creates every matrix. `regeneration_contract.json` gives the expected exact serialized initial-bit prefix SHA256. Trial files are outputs, not essential Git inputs. On an existing accepted result, the independent CPU audit is:

```sh
OPENBLAS_NUM_THREADS=1 python3 src/hpl-julia/audit_captures.py \
  --result .porting-state/portable_julia/runs/20261019T233339230867Z_hpl/result.json \
  --output /tmp/hpl_audit.json
```

Use an existing NumPy2.2.6 environment for that command; it launches no GPU work. `--run-root` relocates archived run directories. Large failed/accepted raw captures remain in ignored local research storage. Their exact locations and hashes are recorded, not falsely claimed to be recoverable from hashes alone.

## Feedback and observed effort

Native/shared readiness retained build/link/MPI-linkage and allocation/oracle adapter failures. An omitted runner `structured:true` flag created malformed25-row diagnostic bundles; they are incomplete and excluded. Their logs remain, but earlier files overwritten by repeated diagnostic filenames are an explicit preservation gap. An ignored per-model environment metadata key failed to control BLAS threads; selected processes instead use explicit `env OPENBLAS_NUM_THREADS=1`. These are shared preparation costs, not language/compiler failures.

CUDA.jl and KA passed their first full program. JACC's first program accidentally used uppercase `JACC.Array`, which resolves a host `Base.Array`; the actual-device-input observer rejected the host address before mathematical GPU work. Changing to the installed lowercase `JACC.array` API passed all five comparisons. This was a runtime allocation/API repair, not a compiler rejection or unsupported feature. There are zero authored mathematical GPU kernels and zero such device-JIT attempts; complete host-program evaluations are counted separately.

Actual prospective input/cached-input/output/reasoning counters have separate native, target, verification and annotation boundaries. Cached input and reasoning are subsets, not additional totals. Target costs include inherited context and feedback; KA/JACC reuse accepted shared helpers. They describe marginal ordered workflow effort in this library-backed class, not cold-start intrinsic framework cost or recovered historical consumption.
