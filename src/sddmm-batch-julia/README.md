# Batched SDDMM: cuSPARSE orchestration, zero authored device kernels

The native source contains no authored GPU kernel. It calls cuSPARSE sampled dense-dense multiplication into strided CSR outputs. CUDA.jl, KA and JACC versions orchestrate that same vendor API; loading a framework does not exercise its device compiler or demonstrate a framework kernel translation. The historical Julia mcpr alias is unrelated and is preserved with its target source.

## Verified numerical scope

The new primary configuration is explicitly source-shaped: every batch in a case has the same sorted unique CSR structure, while dense A/B values differ in every batch. A CPU witness using the unchanged original init_matrix/init_csr shows zero structural differences and three value differences across four batches. The source reseeds srand123 on every initialization, so its original CSR patterns repeat. This source-domain evidence justifies the named repeated-pattern primary; it does not erase failures on broader inputs.

Five cases use batch counts1,3,4,32,2 and (M,K,N,NNZ)=(1,1,1,1),(17,11,19,37),(33,17,35,67),(32,33,31,64),(1,7,9,4). There are42 distinct dense batch pairs and2436 sampled outputs, with odd/non-square dimensions, empty CSR rows and a single-row case. The batch32 case retains the source batch count on compact matrices; original1024/4096 sizes, random inputs and1000 repeats are unmeasured.

A values are quarters and B values eighths. The sum of absolute integer-scaled products in units1/32 is below2^24, so products and every partial sum are exactly representable in Float32 regardless of reduction order. The fixture computes sampled inner products; an independent read-only audit constructs complete dense products as sums of integer rank-one outer products and then traverses CSR samples. This proves the selected exact binary-rational domain, not arbitrary large-K/Float32 accuracy or vendor accumulator internals.

All20 primary artifacts are bitwise identical and match the independent oracle. Each contains160079 lossless Float64 words:78637 input-prefix words plus81442 output/state words. Every sampled value, actual GPU A/B, CSR offsets/columns, actual pre-compute initial C and400 guard words are checked exactly. Beta0 overwrites nonzero initial C; structural arrays remain unchanged. Full inputs and guard values are exact, with atol=rtol=0. Structured uncomputed error metrics are null; actual runner dual-reference errors are computed separately.

## Preserved broader vendor failures

The initial control varied row-offset distributions across batches. cuSPARSE12001 native and CUDA.jl, plus an isolated cuSPARSE12510 Julia diagnostic, returned SUCCESS but failed the unchanged mathematical oracle in all15 captured trials. Every output exactly matches using the first batch's row offsets together with each batch's own column indices and dense data. Actual inputs, initial C and guards match exactly. These complete failed artifacts, hashes and the independent hypothesis replay are retained in vendor_diagnostics.json. They remain failures and are excluded from the new primary result.

The reviewed NVIDIA CUDA12.0 SDDMM documentation advertises batched CSR support through CsrSetStridedBatch/DnMatSetStridedBatch; no explicit common-row-offset restriction was found in that section. The observed behavior is bounded to actual cuSPARSE12001 and12510 on this device and fixture. It is not a universal library/API/hardware conclusion and not a KA/JACC limitation. The broader failed domain is not certified. Archived diverse fixtures and diagnostic replay mappings retain original bytes; old configurations must not be rerun against the new primary fixture by mistake. A hash-bound descriptive erratum corrects stale top-level vendor metadata in the alternate-library diagnostic; actual source, dependency and dladdr/version logs bind12510 throughout.
