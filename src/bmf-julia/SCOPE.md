# BMF named complete optimizer pipeline

The original cuBool UInt32 specialization performs Boolean matrix factorization: a reconstructed cell is `(A[i] & B[j]) != 0`. It uses seeded FastKISS initialization, random bit-mask proposals, a Metropolis accept/reject rule, alternating row/column updates, periodic distance polling, cooling, and best-restart selection. This study includes that complete optimizer, rather than only its Boolean product or a fixed-factor distance kernel.

Three generated packed Boolean matrices are 17×33, 65×97, and 257×529. Latent dimensions are 5, 13, and 20; iteration limits are 7, 105, and 21. Every case has two sequential restarts in one active slot. This is a source-supported constructor configuration. The CLI chooses two OpenMP slots for two or more restarts; concurrent slot scheduling and critical-section seed interleaving are outside this deterministic control. The missing MNIST asset, eight concurrent CLI restarts, and 10,000-iteration workload remain unmeasured.

The timed region is the sum of the three complete `runMultiple(2)` pipelines, including factor initialization, both distance kernels, alternating updates, host control and synchronization, polling, cooling, and best-factor device-to-host copies. Matrix construction/upload, allocation, guards, actual input readback, and checking are outside. A complete pipeline warmup precedes all five checked trials. The reported mean retains trials 2–5.

The independent Python oracle explicitly evaluates every candidate against all opposite-factor entries. It implements modulo-2^32 FastKISS separately, with Float32 host control and source pass-by-value RNG behavior. Final active and best factors and all restart scores are checked in full, with actual packed-device-input readbacks and guards on all four device allocations. Positive-temperature decisions have a reported minimum distance from the random/probability boundary, rather than an asserted universal transcendental equivalence. The fixture defines unused C padding and tail bits as zero; padding is captured exactly.

No claim is made about optimum factorization, stochastic mixing, real-data reconstruction quality, or the optional uninstantiated floating-factor specialization. The original source remains unchanged. Allocation/guard instrumentation and one-slot scheduling are disclosed study controls, not mathematical repairs.
