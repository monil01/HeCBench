# Packed learned-bit-plane LUT-GEMM study

This is the source compressed GEMV (one input vector), using learned per-group/per-plane/output half scales and optional offsets. Set weight bits mean+1, unset mean−1. These scales are not fixed powers of two. The historical Julia dense Float32 matvec omitted the packed representation, scales/offsets and lookup kernel; its original source and Makefile are preserved. Native sources are archived byte-identically and the selected original native GPU bodies are unchanged.

## Numerical contract

Seven named legal cases cover output counts34/514/2050, input lengths64/128/256,8/4/3 planes, group sizes32/64/128, bias/no-bias, even partial output tiles and a zero-input control. Every packed bit position contributes under the dense nonzero input cases. Source block256, M tile2048, K tile32biased/64unbiased are retained. Odd output counts and partial K tiles are outside source safety bounds and are not run.

The independent CPU oracle expands each packed sign bit and computes the dense weighted matvec using integers, without copying the lookup algorithm. Inputs are quarter-integers, learned scales/offsets are±1/128. All half intermediates and any atomic partial-sum order are integer multiples of1/512 with absolute integer bound≤2048, hence exactly representable in half. The predeclared acceptance is exact, not an average error threshold. This is a dense exact-arithmetic class; it does not certify arbitrary FP16 rounding, quantization accuracy or trained-model quality.

Each of20 captures contains319609 Float64 words losslessly encoding actual half/UInt32 fields:156931 exact input-prefix words,5230 complete outputs,156888 actual input echoes and560 guards. Full output values match the independent integer oracle and both GPU references in every trial. Every input byte and guard is checked. Output payload starts at+.5 outside timing, then is cleared inside timing before the original LUT operation. Raw outputs remain saved, without canonicalization. audit_saved_outputs.py independently rechecks all archived artifacts without another GPU series.

## Mapping and timing

All versions construct the source shared256-entry table per8 inputs, expand it incrementally, reduce byte lookups with learned half scales and update adjacent outputs with real packed half2 atomic addition. Julia uses CUDA backend inline half add/mul/FMA and atom.add.noftz.f16x2 instructions through its own CUDA.jl/KA/JACC dispatch: these are backend extensions, not a pure portable abstraction claim. Half storage and arithmetic are retained, with no Float32 accumulator substitution. The native selected SASS contracts half mul/add to HFMA2 despite separate PTX instructions; static selected-function evidence is preserved. It does not establish dynamic FLOP counts or performance causation.

Shared storage is2048bytes with bias and4096without. KA owns local memory and barriers; JACC.shared copies a whole template and adds an entry barrier before the table is overwritten, extra work retained explicitly. Native uses cudaMemset and Julia uses fill! for output clearing; each required clear is inside the matching timing region. Timings sum seven clear+kernel+completion paths. Setup, allocations, inputcopies, JIT warmup, readback, CPU checks and serialization are outside. Five checked in-process trials retain only2–5 in the reported mean; no outlier is discarded.

Native first host-harness build used a device-only half-bit conversion in a host byte check and failed. Replacing that owned adapter check with memcmp repairs no native kernel. CUDA.jl and each portable version pass their first actual GPU candidate/check. Shared operator/helper/oracle work is attributed once to the reference phase and reused KA then JACC. Prospective usage windows include repeated/cached context and coordination and overlap the outer workflow; they are not additive or exclusive billed costs. Historical creation cost is unknown. Root alone commits shared/reference work and each verified variant separately.
