# Gray–Scott reaction-diffusion: source pencil pipeline

The native source advances A_t=Da Lap(A)−A B²+F(1−A) and B_t=Db Lap(B)+A B²−(F+k)B using explicit Euler on a Cartesian grid. At outer faces, the missing neighbor repeats the center value: the discrete zero-flux operator. The historical Julia source genuinely implements this mathematics, but fuses a timestep into one kernel and uses a different random-input generator. It is preserved intact. The current study restores the original ten-launch timestep and nine-buffer layout for all four versions.

## Numerical and scientific scope

Four named fixtures use16³ nonuniform data for5steps,32³ with the source10³ central patch and zero perturbation for4steps,16³ exactA=1/B=0 equilibrium for3steps, and16³ affineA/B=0 diffusion-only data for1step. Da=.16,Db=.08,dx=.5,dt=.25,F=.0392,k=.0649 are retained, except the explicitly separate diffusion-only control setsF=k=0. All actual Float32 initial concentrations and parameters are fixed before translation. This is a short-time discrete-operator study, not the original128³×10000step CLI, a periodic-boundary study, calibrated chemical prediction, pattern-morphology validation or a continuum convergence experiment.

An independent Float64 solver uses full global-neighbor differences and the explicit equations, without pencil tiling or shared-memory GPU code. It checks every value in all nine final fields with a predeclared1e-6+5e-6relative budget. A/B are after the final update; the seven scratch fields contain derivatives, reaction rates and diffusion from immediately before that update, as in the source. Every actual initialA/B input bit and all buffer guards are exact. Exact equilibrium, final species nonnegativity, zero-flux mean diffusion and diffusion-only mean mass provide additional controls. The fixed budget is an engineering Float32 tolerance, not physical model error; per-field actual error, magnitude, budget fraction and zero-reference behavior are retained.

## Mapping and timing

The original native kernels are unchanged. Each timestep launches three axis derivatives forA, assembles its Laplacian, repeats forB, then computes reaction and updates both species. There are six selected native kernel types and130 launches over13timesteps. Native source also contains periodic kernels, which are preserved but outside certification.

All versions retain the source two-pencil workgroup geometry: x uses(M,2) threads and y/z use(2,M), with grid(M/2,M). Pointwise kernels useM threads andM² blocks. CUDA.jl uses dynamic shared memory and CUDA block primitives. KA uses only its own local-memory/index/barrier APIs for device code. JACC uses its own shared/sync_workgroup APIs and reconstructs local/group positions from framework global indices. Only CUDA backends have actually been verified; no cross-backend result is inferred.

KA's local-memory capacity is specialized at compile time, while native/CUDA.jl shared memory is dynamic. JACC.shared copies the whole2M-element template into the tile and synchronizes before payload overwrite and the required stencil barrier. The installed CUDA backend initializes this template only with y==1 lanes: M lanes for the x pencil and two lanes for y/z. That extra copy/barrier is a source mapping covariate, not a measured allocation of runtime cost. JACC explicitly requests128/256 shared bytes for derivative tiles and zero for pointwise kernels. The template carries no operator input: every tile value is overwritten with the concentration before use.

The named region sums four continuous whole-timestep batches, with one completion per batch and no added host synchronization between stages or steps. Allocations/reset, input readback, full output/oracle checks, serialization and complete-pipeline compilation/warmup are outside. Per-case times remain separate. All five checked trials are retained and the mean uses2–5 without outlier removal. KA kernel objects and JACC LaunchSpecs are constructed inside their launch functions, so frontend setup is an implementation covariate. Host dispatch, shared initialization, compiler specialization and final machine instruction effects are not isolated; no fundamental abstraction ranking, pure device timing or roofline claim follows from these clocks.

Before the first GPU trial, offline native PTX inspection guided Float32 rate expressions and explicit Euler muladd. Final SASS was not captured, so identical arithmetic instructions are not claimed. Every GPU model passes its first current candidate/check. One owned fixture generator initially required unavailable NumPy; that shared T1 preparation error is preserved, and a stdlib oracle replaced it before any GPU run. Shared algorithm/oracle/native adapter work is attributed once to the reference phase and reused KA then JACC. Prospective usage includes repeated/cached context and coordination; overlapping outer/model windows are not summed or treated as exclusive billed or intrinsic cold-start framework costs. Historical creation cost is unknown.
