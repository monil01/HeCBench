# Mean-shift clustering study

## Algorithm, data and scientific checks

Both global-memory and tiled kernels execute the original 10,000-point, 3D all-pairs weighted update for 1,000 synchronized iterations. Each point moves to its Gaussian-weighted neighbor mean. The cutoff constant 60 applies to squared distance, so the Euclidean radius is √60; sigma is 4 and the exponential denominator is 32. GPU kernels retain all 10,000 queries and all 10,000 neighbor visits per update.

The source CSV has 21 unique Float32 rows repeated into three widely separated clusters. The independent CPU oracle groups only identical rows with their exact multiplicities and computes the same mathematical recurrence in Float64. This reduces checking work, not GPU work. Every trial verifies all 30,000 final coordinates, finite values and the original squared distance-to-center bound of 10. A predefined absolute coordinate tolerance of 0.01 is used; observed maximum Double error is 6.0286e-5. All 40 saved artifacts across both configurations, four models and five trials are byte-identical on this fixture. The 30,144-value input prefix serializes the actual padded input copied to device and is checked byte-exactly separately from output tolerances.

These simple, low-entropy clusters converge rapidly, but the full 1,000 updates are still executed. The timing average is dominated by the converged portion of that trajectory. No general convergence-rate, early-stopping, bandwidth-selection, difficult cluster-quality or real scientific dataset claim follows from this fixture. Near-cutoff cases, noisy clusters, large dimensions, large-N scaling and other input regimes are unmeasured. Self-neighbors ensure a positive weight denominator, and separated convex neighborhoods retain the three known clusters.

## Native repair and implementation mapping

The original tiled kernel reads its own query position for all 157 × 64 lanes before the final output guard. The last 48 lanes read beyond the original 10,000-row allocation. This is a static source access witness, not an observed sanitizer failure. The named study gives both ping-pong buffers 10,048 rows and defines the 144 padded Float32 entries as zero. The unchanged kernel bodies, logical N, valid queries, neighbor order, barriers and outputs are preserved. This is an independently justified native host-allocation repair for the tiled configuration: native_reference_repaired=true and exclusion from untouched-native aggregates. The original exact-allocation tiled CLI is not certified. Base already guards tid<N; extra capacity is unused and is disclosed as named fixture storage, not a base algorithm repair.

All four retain 64 lanes and 157 blocks. Tiled scratch is 1,024 bytes: 192 Float32 AoS coordinate values plus 64 validity values. KA uses @localmem and @synchronize; JACC uses shared and sync_workgroup with an explicit zero/1,024-byte launch request. No foreign CUDA device API is required by KA/JACC, so both are framework device kernels. JACC adds zero-template reads and one staging barrier per launch. Native has split shared arrays while Julia versions use one arena; alignment, compiler vectorization, registers, spills, occupancy and read-only cache code generation are unknown. The 120-KiB input fits cache; logical load counts are not measured DRAM traffic.

The study native compiler uses -O3 and ordinary Float32 source expressions. The original Makefile enables --use_fast_math; its production fast-math performance configuration is not certified by these measurements. Both source configurations and actual flags are recorded. Standard exp lowering may differ by compiler and framework, without an inferred numerical or hardware cause.

## Timing, evidence and effort

Each process explicitly warms a full 1,000-update run. Each of five in-process outer trials resets outside the clock, then times the 1,000 launch/synchronization/ping-pong steps and divides by 1,000. The first outer trial is discarded and the last four averaged. All transfers, resets, CPU checks and serialization are outside timing. The initial ten-update diagnostic and its logs are retained separately and were used only to establish feasibility; no fastest-series selection occurs.

The old CUDA.jl file aliased an unrelated touch/PASS program. Its restoration, semantic helper/oracle drafting, native adapters and tiled host repair are separately recorded. Each portable target passed one candidate, two compiler checks and two kernels without repairs, reusing the already audited reference body. This is not a global first-program-success claim. Historical translation effort is unknown. Prospective reference, KA, JACC and annotation windows are separate; broad workflow overlaps them, includes cached/context/coordination tokens and is not additive or exclusive billing.

Absolute acceptance and independently computed dual-reference comparisons remain valid. No numerical acceptance or timing series changed.
