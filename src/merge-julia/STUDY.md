# Merge-path study

## Exact scalar operator and domain

This benchmark merges two sorted scalar sequences using global co-ranked diagonal partitions and shared-memory merge windows. It is a domain-neutral ordered-data primitive; the source identifies no specific scientific application or dataset. All four native types are covered: UInt32, Float32, UInt64 and Float64. N=100,000 per input, 112 blocks, 32 lanes for diagonal search and 128 lanes for merge windows match the source policy. Each window has 512 outputs; the source's 511-element advance is preserved, while corrected per-block guards prevent overlapping output intervals.

The named fixture has positive finite or unsigned keys with structured duplicates, source-style 1,024-element sentinel padding and different input ranges. Source floating negativeInfinity is actually FLT_MIN/DBL_MIN and positiveInfinity is finite maximum, so negative, subnormal, NaN, infinite and sentinel-collision cases are not certified. UInt64 inputs include a high bit and meaningful low bits, extending beyond the original host RNG range. No key is converted to a floating surrogate. Scalar ordering and partition coordinates are exact; no external payload/record identity stability is claimed.

An independent serial stable merge and origin-prefix counts produce all 200,000 expected output values and 226 path coordinates. Every saved trial also serializes the actual 202,048 input values, including padding, in its original storage type. That prefix is compared byte-exactly separately from output acceptance. All outputs and path values are CPU exact with zero tolerance; all 80 artifacts match the typed CPU bytes across four models, four types and five trials. UInt64 low-bit accuracy is checked by exact bytes, not Float64-coerced error metrics. Sortedness, multiplicities and complete output coverage are independently audited, extending the original native and historical Julia checkers, which inspected only the first half of the merged array.

## Native defect, conditional correction and reference repair

Original UInt32 execution on the legal duplicated fixture failed with CUDA700. A localized probe showed successful diagonal execution followed by merge-window failure. HPC SDK CUDA12.9 compute-sanitizer identified an invalid shared read at address0xfffffffc in kernels.h:218. The original unsigned, unbounded local search can underflow when one input window is exhausted. Initial later dtype failures used the same poisoned context and are not independent precision-failure evidence. The system sanitizer's missing injection library is separately recorded as an environment failure.

The first correction introduces bounded local co-rank search and passes full UInt32 output. Source inspection additionally identifies rejected valid x==A_length global splits and fixed-size output writes crossing block intervals. The final conditional reference admits that boundary and guards each block's output interval/global length. These extra safeguards are source-derived and are not reported as observed numerical failures. All four corrected types pass full CPU output checks; corrected UInt32 memcheck reports zero errors. Original native files remain unchanged. A byte-preserved main and patched header, exact diff, candidate provenance, sanitizer evidence and diagnostic logs are retained. All primary results are flagged native_reference_repaired and excluded from untouched-native aggregates.

The historical CUDA.jl implementation sorted a concatenation with a generic GPU sort. It did not translate the two-stage native merge-path algorithm. The current reference restores the corrected source algorithm and the complete numerical contract. Shared preparation, native diagnosis/correction and reference restoration are costed separately from portable target drafts.

## Per-model mapping and timing

Native retains separate shared arrays and volatile counters. Julia implementations pack 1,028 actual typed values plus four UInt32 counters into a UInt32 arena and reinterpret only the value region. This preserves UInt32/UInt64/Float32/Float64 key storage and UInt32 metadata without floating-point counter emulation. Logical shared sizes are 148 bytes for diagonal state and 4,128/8,240 bytes for 32/64-bit merge types. Alignment/padding, register/spill behavior and read-only cache code generation are unmeasured.

KA uses its local-memory and barrier APIs. JACC uses shared vectors and sync_workgroup with explicit required scratch, adding zero-template reads and a staging barrier. Neither portable target calls a foreign CUDA device API; both are framework device kernels. Host allocation/completion glue is tested only on the pinned NVIDIA backend, so this is not a cross-device portability result.

Each process warms the complete kernel pair before five in-process trials. Each timed trial contains ten kernel pairs, each with completion, reported as mean time per pair. The first outer trial is discarded and the final four averaged. Resets, transfers, CPU checking and serialization are outside timing. The canonical fixture is reused, unlike the source host workflow that regenerates/sorts/transfers random inputs for each original run. The logical 1.6/3.2-MB active footprint and structured duplicates constrain cache/distribution conclusions. Comparison/copy work must not be assigned ordinary floating-point operation counts without a convention. No measured roofline, DRAM-traffic or bottleneck attribution is supplied here.

Observed pair means in microseconds, in CUDA / CUDA.jl / KA / JACC order: UInt32 27.212 / 38.058 / 51.086 / 73.029; Float32 26.674 / 37.245 / 48.904 / 60.652; UInt64 30.493 / 39.673 / 49.045 / 70.378; Float64 32.337 / 38.119 / 52.943 / 65.635. All required samples and dispersion are retained. Hardware versus host/runtime/code-generation causes have not been measured.

## Effort and usage scope

Each portable target passed one candidate and four frontend compiler-check commands with two generic kernel definitions and zero repairs. Eight entrypoint/type combinations are covered; internal compiler-pass counts are unknown. This reuses the already audited shared/reference algorithm. Native reference repair has two explicitly recorded versions, one runtime-feedback repair and one source-derived safeguard revision, with primary and diagnostic builds separate. Historical effort is unknown; a first target candidate is not global first-program success.

Translation windows close before the next draft. A parent-requested meanshift metadata review occurred after both merge target windows closed. To avoid overlapping benchmark windows, the broad merge workflow ended after verification and excludes this later annotation. Annotation has its own separate window, and the broad count must not be claimed as full benchmark consumption. All windows include context, cached context and coordination and are not exclusive billing; overlapping broad and child counts are not additive.
