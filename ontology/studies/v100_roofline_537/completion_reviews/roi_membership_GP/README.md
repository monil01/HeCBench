# G–P source ROI membership proposals

Private root-merge proposals only: `proposed_stage_patches.json`, generated by `prepare_proposals.py`. No shared changes, GPU/build/tests or Git actions.

Selected names: **gabor, gamma-correction, pool**, all four models (12 selected successful records). heat2d was inspected but deliberately not enriched: current selected profiles all failed and contain no valid observations. Scope remains G–P. Three names are sufficient for the bounded up-to-six assignment.

## Proposed changes

18 existing stages only; no new record authority. Twelve timed family stages receive `source_timed_closure_inclusion_proved`. Three native warmup stages plus three dormant legacy CLI stages receive `source_setup_exclusion_proved` with explicit callsite kind explaining the exact exclusion (dormant code is not claimed to execute during setup). Warmup/dormant regexes become null, because the same compiled scientific kernel also occurs in the timed closure and duplicate regex matching otherwise yields ambiguous attribution. This is stage-callsite normalization, not a runtime phase claim.

- **Gabor:** native study main's repeat launch is between steady-clock boundaries; renamed historical main is dormant. Julia entry binds prepare→named kernel closure→study_main's timed repeat. JACC parallel_for explicitly supplies the named gabor callback. CUDA.zeros fill kernels remain unassigned; no unsupported setup inference by generic fill name.
- **Gamma correction:** native timed dispatch is distinct from preceding warmup; included legacy_main is dormant. Julia run! closure supplies explicit kernel! to common study(run!), which places run! between start/time synchronization. H2D reset precedes timing. JACC callback is an explicit argument rather than a generic wrapper-name inference.
- **Pooling gradient:** native repeat loop is inside timer; warmup is outside. Julia prepare→launch!→run_batch! is inside common timer. CUDAjl study adapter removes exit(main(ARGS)), so the historical main's candidate callsite is dormant and its duplicate regex disabled. KA binds the named kernel instance; JACC dispatch explicitly binds pool2d_grad_kernel!.

## Proof bindings and limitations

Every patch gives compressed/raw parent review SHA, exact record key/index and original canonical record hash, stage key/index and original stage hash. Exact source callsites, source SHA/snippets, timer line locations and named callback chain are included. Seventeen files used for proof are byte-identical to bindings in the **actual selected frozen profiling plans**, not merely current canonical source guesses. Selected manifest/plan/derivation, configuration and numerical result hashes are explicit. Existing coverage, steady-state, launch-census and bottleneck qualifications are preserved.

The selected observed identities were matched read-only against the proposed stage regexes: at most one stage matches each identity. This checks unique semantic-family matching only. It does not assert the first observed launch was timed: these device families also occur in warmup. No multiplicity extrapolation, whole-family/elapsed ROI aggregate, causal mechanism, or primary timing claim follows. Observed fill kernels with no existing candidate stay unassigned.

## Root merge protocol

1. Verify parent gzip/raw SHA and exact canonical record/stage hashes; fail closed on drift.
2. Verify each source SHA and selected profile/configuration/result binding.
3. Preserve historical gzip bytes and receipt. Apply only the listed stage updates in a new reviewed source snapshot or provenance-bound replacement; do not create a second overlapping `(benchmark,model)` authority in roi_reviews.
4. Existing summarizer requires exactly one regex match plus proof/status before assigning source closure membership. It should retain its `source_closure_membership_proved_sample_phase_unproved` label; do not set dynamic sample timing or whole-ROI flags.

The proposer does not modify kernel_mappings, existing derived counters, profile observations, primary measurements or source. Packaging usage is shared profiling annotation only, not historical translation effort.
