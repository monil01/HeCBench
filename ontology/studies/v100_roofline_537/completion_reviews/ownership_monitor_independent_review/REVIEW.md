## Historical finding

Retained batch064 native provenance reports rc-15, an `external_gpu_activity_detected_own_profile_stopped` stop at15:18:16.699549, PID333309, process_name `[No data]`, GPU6 UUID. Its execution log contains all five correct72089820-value trial rows. The selected source constructs the reported private directory from `getpid()` at study_native.cu:48 and prints that directory in each trial at:59. The fifth row ends `/pid333309`. This establishes that the target used that numeric PID; it does not establish contemporaneous PID generation/startticks, the monitor's failed operation, or whether the NVML row denoted a stale target or a subsequently reused PID. No proc-status exception detail was saved. The historical externally-labelled stop is therefore an actual guard termination with **unproved foreign ownership**, not an admissible successful capture or proved foreign intervention. Preserve all original facts, stop string, return code and fragments; add a qualified interpretation rather than overwrite them.

The C21 source tries getsid(pid), then an ancestry walk, catches OSError/ValueError without recording details, and classifies every unresolved row as external. A vanished target can therefore take the same classification path as an actual foreign process. `[No data]` is not an ownership credential. The final target's five success rows are not a replacement for successful profiler return, complete counter capture, source stability, quiescence or admission.

## Narrow prospective state machine

1. Before launch record guard/profiler leader PID, UID, session ID, startticks, boot identity and command binding. For each live observed GPU PID and each verified owned descendant, read process identity twice around session/ancestry validation. Cache only stable exact-generation identity; retain the complete parent chain and how it reaches the freshly spawned session/leader. A merely equal numeric ancestor is insufficient if its generation is unknown or changed. Re-read ancestor identities too. Reject unstable or contradictory observations. A live session-changing descendant is not accepted solely from same UID or command/name.
2. Distinguish **live proven owned**, **live proven non-owned**, **unresolved observation**, and **previously proved owned generation now exited/unreadable**. Different live startticks from cached PID is immediate reuse/unknown-new-generation handling, never owned-cache acceptance. Permission errors, parse failures, disappeared ancestors or absent generation proof stay unknown. Record actual errors and raw GPU rows, not only the eventual category.
3. Holding a pidfd for a proved generation and polling it can provide retained identity/liveness evidence for that generation. It does not attach that identity to an NVML row containing only a numeric PID after exit. Never allow a dead cached PID merely because it was once ours; an intervening short-lived reused generation is not excluded by such a cache. Same UID, session number, timestamp, known executable, `[No data]`, completed output, or bounded elapsed time alone cannot prove GPU-row generation.
4. A tightly bounded **observation-only deferral** can avoid immediately terminating the still-owned profiler while an already-proved child is exiting. During deferral collect raw GPU snapshots plus exact live-generation/session checks, and continuously enforce foreign-process, resource and wall gates. It must not accept unknown ownership as owned, extend the scientific timed region, reset the main deadline, signal the unknown PID, or silently suppress true non-owned live rows. Choose an explicit short budget in root review, record each deferred observation, and halt/qualify unresolved cases at expiry. A row disappearing later is evidence of resolution of the present observation, not proof of uninterrupted exclusive use earlier. If strict exclusive-ownership admission is required, retain an ownership-interval hold even after disappearance unless an independently reviewed stronger identity/completion argument establishes the interval.
5. Prefer recording/quiescing an already naturally exited profiler to sending SIGTERM solely because an unidentifiable numeric row survived briefly. Still do not mark that capture admitted while any ownership interval remains unproved. Check ownership again before every signal of **our** session and pin the intended generation. Never signal the queried unknown/foreign PID. All cleanup remains confined to a proved current owned generation/session; no cached-dead identity authorizes a signal.
6. Final process completion must include target's original five checks, rc0 with no actual stop, required counters/metrics, stable source/tool bindings and own-session quiescence. GPU idle/quiescence alone does not identify a prior row or repair an earlier provenance gap. Store a distinct observation/ownership qualification for audit and method strata, separate from numerical success, timeout, compiler and translation attempts.

## Recommended authority split

The smallest immediate correctness fix is **taxonomy and diagnostics**, distinguishing unknown/teardown from proved foreign activity. Any grace/completion policy affecting admission needs an explicit separate scientific-method review. A conservative cache-only proposal that ends in `unresolved_prior_own_teardown` is safe but may still hold benign captures; disclose this operational limitation rather than promise recovery. New collector bytes must be independently reviewed and adopted through a new controller frontier. C21 remains pinned for existing queues, and075 must stay execution-held until an exact new source authority is incorporated. No retroactive reclassification into successful064 counters is justified.
