6. Full new scratch files remain retained even after failure; the full SHA/size manifest is written before any future disposal decision. This collector never cleans opt-in tmpfs. Root must separately persistently archive and fully verify every required raw file before any later authorized disposable-only cleanup. No primary raw deletion, automatic relocation or hash-only evidence substitution is proposed.

## Limits and nonclaims

The monitor is a sampled **user-space watchdog**, not a hard tmpfs quota, memory reservation or guarantee against external allocation bursts. Its tree scan and resource checks add observer overhead; they do not change primary accepted timings. Logical bytes are conservatively counted, including independent hardlinks if present. A dedicated container/cgroup/mount quota is not requested or assumed. No RLIMIT_AS is applied to CUDA/Julia's large virtual address space. If a strict kernel-enforced allocation ceiling is required, this proposal is insufficient and must remain held.

Tmpfs is volatile. Current capacity permits a bounded SU3 proposal but does not authorize future writes or guarantee resources at launch. The helper rejects changed mount/directory/cgroup identity, missing required accounting, symlink/special entries, wrong owner/mode, exhausted reserves, unreviewed sources or any non-SU3 benchmark. It does not upgrade the scientific scope, certify kernel-replay safety, bypass method gates or infer whole-ROI coverage. A root-reviewed memory policy and new frontier adoption are prerequisites.

Source-only inspection was performed; no syntax import, compile, test, build, GPU query or run was performed. Any later runtime validation belongs to a separately authorized profiling infrastructure phase, not translation attempts.
