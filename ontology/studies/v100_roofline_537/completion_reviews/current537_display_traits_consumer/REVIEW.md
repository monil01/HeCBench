## Gates and failure behavior

Loader checks exact externally supplied root authority SHA, approved status/population, actual loader bytes, canonical overlay path/SHA, and exact audited v3 root source-adoption receipt SHA/status. Before each model entry it rechecks authority and overlay bytes. Entry validation reads under short existing read-only metadata LOCK_SH.

For each affected benchmark/model, it requires the current ledger-selected completed manifest to match the exact approved manifest SHA/path; selected configuration ID/raw-config SHA/result SHA must match contract and frozen plan; compressed plan/provenance SHA must match; actual result-file SHA must match; source-bindings map must match actual frozen plan+provenance; current implementation metadata SHA and identity must match, and exactly one implementation configuration must join the same result SHA. Its source proof packet must be present in the adopted source receipt and hash-match the exact patch/stage proof. Every explicit .jl/.cu/.cpp/.c/.h/.hpp/.py proof source must match both selected-profile binding and current source bytes. Mapping overrides additionally require all their explicit source excerpt hashes, metadata expected field/value and selected capture joins. Curated aliases require current domain SHA and exact original-field text equality.

A model-level capture/source/config failure withholds only that model's decorations. An individual mapping/geometry failure withholds only that field; alias-record failure withholds that model's domain aliases. Original records remain fallback. Issues and verified input SHA maps are exported, never silently promoted. A failed authority disables all decorations because no trusted overlay remains. Unknown/null metadata never means absent feature or zero work.
