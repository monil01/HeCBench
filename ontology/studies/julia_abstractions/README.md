# Julia abstraction study layer

Links measured configurations to canonical benchmark IDs and hashes without rewriting automatically inferred ontology/benchmarks records. Generated by tools/export_julia_study_ontology.py from portable paper result snapshots and per-variant local manifests. Keep base ontology claims distinct from reviewed source traits, named input/scope, numerical evidence strength, measured times, and hypotheses.

A benchmark can have several configurations (for example layout AoS/SoA) and each configuration can have different timed regions, logical work, access mapping, and roofline applicability. Never project a compute-kernel roofline onto the original triad host-transfer pipeline. Integer/property benchmarks require appropriate non-FP measurements.

failure_taxonomy.json preserves canonical instruction codes. Failure events link to attempts and configurations; counts require phase attribution and candidate/check deduplication. N3 tolerated drift and P1 disclosed portability adaptations are not failures. Shared setup/reference-correction costs are not original CUDA.jl translation costs. Per-variant partial proxies are not total consumedtokens.

Raw binaries/databases remain local STATE; concise source hashes, configuration contracts, five samples, and portable paper snapshots provide traceability. Profiling CSVs and modeled ceiling equations are in paper/research/data/profiling, separately from required execution timings. Association does not establish causality.
