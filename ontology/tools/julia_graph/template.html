How these relationships are constructed

Scientific scores combine reviewed scientific-family equality (0.45), task-text token overlap (0.25), and method-text token overlap (0.30). Implementation scores compare the same Julia model: class (0.30), device API dependence (0.10), algorithm text (0.20), layout text (0.15), mapping text (0.10), and recorded storage-precision overlap (0.15). Verification scores compare actual origin-matched failure codes (0.50), agreement-kind descriptors (0.30), and qualified outcomes (0.20). They do not rank framework reliability or make contracts interchangeable.

Text overlap uses token Jaccard similarity. These fixed weights are descriptive author choices, not validated probabilities, learned embeddings or performance predictions. Scientific edges require a shared reviewed family or substantial overlap of both task and method. Implementation edges require a shared supported class and recorded implementation-text overlap. Verification edges require a shared actual failure, qualified outcome, or property/execution contract. Missing values add no score. We retain the union of each endpoint's __TOP_K__ strongest positive links, with ties broken by benchmark ID; absent links do not prove dissimilarity. Filters apply to this sparse derived graph, not a new exhaustive nearest-neighbor search. Max. neighbors limits only neighborhood views.

Native-to-Julia links identify versions of the selected benchmark and their recorded contracts. They do not claim every version is an accepted numerical port. New timing means are never inferred here; the inspector displays the recorded per-configuration means of trials 2–5. Failed originals, corrected references, property outcomes and hardware barriers remain qualified. Token windows can overlap; source-token estimates are proxies.

Graph inputs come from the selected __STUDY_POPULATION__-name catalogue assessment; the frozen447 records and previous catalogue similarity index are preserved. The page is self-contained and works offline.
